# WF5007: Widget extension has no @main entry point

**Symptom:** The widget extension does not provide a widget.

**Cause:** None of the extension's Swift sources contains an `@main` attribute. The WidgetKit documentation shows `@main` on the `Widget` (or on a `WidgetBundle` for several widgets) as the extension's entry point.

**Detection:** Swift sources of the target (from its Sources build phase or Xcode 16 folder-based group, minus membership exceptions) are tokenized; comments and string literals are ignored. The finding appears only when every source of the target was located and at least one Swift file exists. With Swift packages, missing files or other unsupported source trees, only a note is produced. No function or type name is required.

**Fix:** Apply `@main` to the extension's `Widget` or `WidgetBundle` type.

Fixtures: `fixtures/err_ios_no_main_entry`, `fixtures/err_ios_main_only_in_comment_or_string`; not reported: `fixtures/ok_ios_widget_basic`, `fixtures/ok_ios_swift_comments_and_strings`, `fixtures/ok_ios_synchronized_folder_group`.

**Evidence level:** static analysis of `ios/*.xcodeproj/project.pbxproj`, plists and Swift sources on Linux. Additionally checked on a Flutter project built with Xcode 26.6 on macOS: no finding on the clean project, and this finding when the condition was introduced into the project files, with the report clean again after reverting ([iOS validation record](../ios-validation.md)). The broken project was not built; the symptom was not reproduced.
