# WF5006: App Group mismatch between app and widget extension

**Symptom:** The widget cannot read data written by the app (shared `UserDefaults(suiteName:)` / container returns nothing).

**Cause (two forms):** (1) the widget's Swift code uses an App Group literal (`UserDefaults(suiteName: "group.x")`, `containerURL(forSecurityApplicationGroupIdentifier:)`) that is not listed under `com.apple.security.application-groups` in the extension's entitlements; (2) the extension and the app both list App Groups but share none.

**Detection:** Entitlements are resolved per build configuration. Only string literals are compared; widgets without any App Group are **not** an error, and a group that only appears in the Flutter code (`HomeWidget.setAppGroupId('...')`, home_widget's API name, not confirmed against its documentation here) is reported as a note, not a finding. Unresolved or unreadable entitlements are skipped with a note.

**Basis and limits:** The entitlement key `com.apple.security.application-groups` and the rule that every target needs the group come from Apple's App Groups capability; the Apple pages that could be read do not mention it. Not verified with Xcode or a simulator.

**Fix:** List the same group in both entitlements files and enable the App Groups capability on both targets.

**Evidence level:** static analysis of `ios/*.xcodeproj/project.pbxproj`, plists and Swift sources on Linux. Additionally checked on a Flutter project built with Xcode 26.6 on macOS: no finding on the clean project, and this finding when the condition was introduced into the project files, with the report clean again after reverting ([iOS validation record](../ios-validation.md)). The mismatch variants were built unsigned for the simulator and the builds succeeded; App Group data sharing at runtime was not run.
