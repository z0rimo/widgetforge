# WF1001: View not supported by RemoteViews

**Symptom:** The widget layout cannot be inflated by `RemoteViews`, so the launcher cannot show the widget. Android developers commonly report this as a "Problem loading widget" placeholder and an `InflateException` in logcat; WidgetForge did not observe either on a device or emulator and does not detect them at runtime.

**Cause:** Home screen widgets are inflated through `RemoteViews`, which only accepts a fixed set of view classes. The check uses two sources and they were compared:

- the `RemoteViews` reference, which lists FrameLayout, LinearLayout, RelativeLayout, GridLayout, AnalogClock, Button, Chronometer, ImageButton, ImageView, ProgressBar, TextClock, TextView, ListView, GridView, StackView, ViewFlipper, AdapterViewFlipper and, "as of API 31", CheckBox, RadioButton, RadioGroup, Switch (the reference states: "Descendants of these classes are not supported");
- the `@RemoteViews.RemoteView` annotations in `android.jar` for API 34, 35 and 36 (identical on all three): the 21 classes above plus `ViewStub` and `AbsoluteLayout`.

`Space` and `View` carry no `@RemoteView` annotation and are not in the documented list, so they are reported. ConstraintLayout, ScrollView, RecyclerView, EditText, CardView, MaterialButton, WebView and any custom or androidx view (including subclasses of supported views such as AppCompatTextView) are reported as well.

**Detection:** Layouts referenced by `android:initialLayout`/`android:previewLayout` of a provider XML are scanned, following `<include layout="@layout/...">` and the `android:layout` of a `<ViewStub>`. Rules:

- Element names are matched exactly; fully qualified `android.widget.*` names and `android.view.ViewStub` are accepted, `android.view.View` and other qualified names are not.
- `<view class="...">` is judged by its `class` attribute.
- `<include>`, `<merge>`, `<requestFocus/>` and `<tag/>` are never reported. For the last two this is a deliberate non-judgement: they are LayoutInflater special tags and their acceptance by RemoteViews has not been verified on a device.
- `AbsoluteLayout` is not reported: the framework annotation allows it although the reference does not list it (deprecated; allowed does not mean recommended).
- Text inside XML comments is ignored, and the reported line is the element's own line.
- Resource qualifiers (`layout-v31`, ...) are not interpreted: every `layout*/<name>.xml` is scanned, so an API-31-only widget such as `Switch` in `layout-v31/` is accepted everywhere.

**Limits:** Static check only. A clean result does not prove the widget inflates, and a successful `flutter build` says nothing about inflation (a build with ConstraintLayout, Space and View succeeds). Custom `RemoteViews` built in code and layouts chosen at runtime are not seen.

**Fix:** Replace the reported tag with a supported view. Typical swaps: ConstraintLayout -> RelativeLayout/LinearLayout/FrameLayout; ScrollView/RecyclerView -> ListView with a RemoteViewsService; CardView -> FrameLayout with a shape drawable background; EditText -> TextView plus PendingIntent; Space/View -> margins/padding or a FrameLayout with a fixed size or `android:background`.
