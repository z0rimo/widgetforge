# WF5005: Entitlements file referenced by the target does not exist

**Symptom:** The target names an entitlements file that is not in the project, so the intended entitlements cannot be applied. Whether a build fails because of that depends on the build: in one observed case (Xcode 26.6, Flutter 3.32.0, `flutter build ios --simulator --no-codesign`, a widget extension whose `CODE_SIGN_ENTITLEMENTS` pointed to a file that does not exist) the unsigned Simulator build still succeeded. What a signed device build or an archive does was not tested.

**Cause:** `CODE_SIGN_ENTITLEMENTS` of the widget extension or its host app points to a file that does not exist.

**Detection:** Resolved per build configuration; unresolvable values are not judged.

**Fix:** Create the entitlements file or correct `CODE_SIGN_ENTITLEMENTS`.

Fixture: `fixtures/err_ios_entitlements_file_missing`.

**Evidence level:** static analysis of `ios/*.xcodeproj/project.pbxproj`, plists and Swift sources on Linux. Additionally checked on a Flutter project built with Xcode 26.6 on macOS: no finding on the clean project, and this finding when the condition was introduced into the project files, with the report clean again after reverting ([iOS validation record](../ios-validation.md)). The App Group variant with a missing entitlements file was built unsigned for the simulator and the build succeeded (a signed or archive build was not tried).
