# WF6003: Provider XML referenced by the built APK is missing

**Symptom:** The launcher cannot read the widget configuration.

**Cause and detection:** The provider meta-data `android:resource` reference (a resource id such as `@0x7f0e0000`) is resolved through `resources.arsc` to a file path (aapt2 may rename it, for example `res/gc.xml` in a shrunk release build); the finding is reported when the id has no file value or the file is not in the archive. If `resources.arsc` cannot be read, a note says the check was skipped.

**Basis and limits:** Resource ids were compared with `aapt2 dump resources` on real debug and release APKs. Produced only by `widgettriage verify <file>`; `doctor` never emits it. Analysis is static and read-only: no install, no emulator or device run.

**Fix:** Make sure the `@xml` resource exists and survives resource shrinking, then rebuild.

Fixtures: synthetic archives in `test/artifact_test.dart`.

**Evidence level:** structure of a built APK read in pure Dart (ZIP, binary XML, resources.arsc); compared with `apkanalyzer` and `aapt2` on real builds on Linux.
