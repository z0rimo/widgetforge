# WF2001: AppWidgetProvider is not registered in AndroidManifest.xml

**Symptom:** The widget never appears in the launcher's widget picker, even though a provider class exists.

**Cause:** A concrete Kotlin/Java class that extends `AppWidgetProvider`, `HomeWidgetProvider` or `GlanceAppWidgetReceiver` exists under `android/app/src/*/{kotlin,java}`, but no `<receiver>` in any `android/app/src/*/AndroidManifest.xml` names it.

**Detection:**
- Classes are read with a small declaration reader (comments and string literals are ignored; constructor parameters and generics are handled; nested classes use the manifest's `Outer$Inner` form).
- Inheritance is followed through classes of the project (`class Impl : BaseProvider()`), using `package` and `import` to identify types. A class is reported only when the whole chain is visible and reaches one of the three base classes above.
- `abstract` classes and classes that another project class extends are never reported (they are bases, not registration candidates).
- A supertype that cannot be resolved inside the project (a library class, an import alias, generated code) makes the answer "unknown": nothing is reported.
- Relative manifest names (`.Foo`, `Foo`) are resolved against `namespace` in `android/app/build.gradle(.kts)` (or the manifest `package`). If no namespace can be read, a relative name matches every class with that trailing name, so two same-named classes in different packages cannot be told apart and nothing is reported.
- A receiver declared in `src/main` counts as registered. A receiver declared only in the manifest of another source set (`debug`, `release`, a flavor) produces no finding but a **note**: builds without that source set do not contain it (observed with Gradle: a debug-only receiver was present in the debug APK and absent from the release APK; the same for a release-only receiver and for a flavor `a` receiver in flavor `b`). A `tools:node="remove"` marker in another source set also produces a note (observed: it removed a main-manifest receiver from the debug APK only).
- WidgetForge is not given a build variant and does not pick one: source sets are neither summed nor is one variant's result applied to all. The merged manifest (library manifests, flavor/build-type combinations) is **not** computed. A receiver contributed by a dependency's manifest is not seen: observed with an Android library module that declared the receiver for an app class, the class was reported although the APK contained the receiver (a false positive for that unusual setup).

**Limits:** Providers declared only through dependencies, generated sources and Kotlin scripts are not analyzed; `import a.B as C` aliases are not supported.

**Fix:**
```xml
<receiver android:name=".MyWidgetProvider" android:exported="true">
    <intent-filter>
        <action android:name="android.appwidget.action.APPWIDGET_UPDATE"/>
    </intent-filter>
    <meta-data android:name="android.appwidget.provider" android:resource="@xml/my_widget_info"/>
</receiver>
```
