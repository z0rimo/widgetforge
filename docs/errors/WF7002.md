# WF7002: Widget extension bundle identifier is not prefixed with the app bundle identifier (IPA)

**Severity: warning (Experimental).** Does not change the exit code. Do not change bundle identifiers on this finding alone.

**Symptom:** Embedding or installing the extension may fail if an app extension's identifier is not under its containing app's identifier.

**Cause and detection:** For an embedded extension whose extension point is `com.apple.widgetkit-extension`, `CFBundleIdentifier` does not start with `<app CFBundleIdentifier>.`. Source counterpart: [WF5004](WF5004.md). Produced only by `widgetforge verify <file>`.

**Basis (see [verify-contract](../verify-contract.md)):**
- A. Stated by Apple documentation that could be read: nothing. No readable page states the prefix rule (the archived App Extension guide only says an extension must live inside a containing app).
- B. Convention: extension identifiers are normally `<app id>.<suffix>`.
- C. Synthetic archives only (`test/artifact_test.dart`).
- D. Needs a real Xcode archive/install: exceptions, the real handling of the containing-app relationship, and the use of the `com.apple.widgetkit-extension` value to mean "widget extension" (the value itself is listed on Apple's `NSExtensionPointIdentifier` page) are unconfirmed.

**Fix:** If a real build confirms the problem, set the extension's identifier to `<app bundle id>.<suffix>` and rebuild. Otherwise leave it.

**Evidence level:** structure of an IPA read in pure Dart; no real Apple build was available, macOS/Xcode NOT RUN.
