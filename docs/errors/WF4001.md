# WF4001: Dart entrypoint named by FlutterActivity not found

**Symptom:** A secondary FlutterActivity (for example a widget configuration screen) has no Dart function to run for the entrypoint it names.

**Cause:** A `FlutterActivity`/`FlutterFragmentActivity` subclass selects a Dart entrypoint that does not exist as a top-level function.

**Which configuration is read** (documented order: a method override replaces the manifest meta-data, which replaces the default):
1. an override of `getDartEntrypointFunctionName()` whose body is exactly one string literal (`= "name"` or `{ return "name" }`),
2. otherwise `<meta-data android:name="io.flutter.Entrypoint" android:value="name">` on the activity,
3. otherwise the default `main`, which is not checked.

The library is `getDartEntrypointLibraryUri()` / `io.flutter.EntrypointUri` in the same way. A `package:<this project>/...` URI limits the search to that file; a URI of another package or an unsupported scheme is not verifiable and nothing is reported; with no URI, every `.dart` file under `lib/` and `bin/` is searched.

**Not reported (unknown):** names or URIs that are not a single literal (constants, concatenation, several statements); activities that override `provideFlutterEngine()`, `getCachedEngineId()` or `getCachedEngineGroupId()` (a cached engine already runs its own entrypoint); anything set through Intent extras at runtime.

**Declarations:** only top-level functions count. Text in comments or strings, methods inside classes and variables with the same name do not.

**Reachability (observed, reported as a note):** a function in a Dart file that `lib/main.dart` does not import or export (directly or transitively, through `import`, `export` and `part` with relative or `package:<this project>/` URIs) is not part of the compiled program: in a release build of an isolated sample the entrypoint was missing from `libapp.so` until `main.dart` imported the file (re-verified). WidgetTriage adds a **note** (not a finding) in that case, because the build target (`flutter build -t`) is unknown; if some directive cannot be resolved, or `lib/main.dart` does not exist, the note says reachability is unknown. A clean report therefore does not mean the entrypoint is reachable unless no such note is present. Conditional-import targets are all followed; generated code and other packages are not.

**Fix:**
```dart
@pragma('vm:entry-point')
void widgetMain() => runApp(const MyWidgetConfigApp());
```
or correct the name returned by the activity (or the meta-data value).
