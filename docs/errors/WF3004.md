# WF3004: Widget configure activity is not registered

**Symptom:** The configuration activity named in the provider XML cannot be started when the widget is added.

**Cause:** `android:configure` in the provider XML names an activity that has no `<activity>` entry. The `<activity>` manifest documentation says an activity that is not declared in the manifest is invisible to the system and cannot run, and the Glance widget configuration documentation (which the Views configuration page defers to) describes declaring the configuration activity like any other activity that accepts the `ACTION_APPWIDGET_CONFIGURE` action. What exactly the launcher does in that case is not documented and was not observed here.

**Detection:**
- Names are compared as fully-qualified class names. `android:configure` is documented as a fully-qualified name; manifest names such as `.Foo` are resolved against the module `namespace`. A same-named class in another package is therefore **not** treated as the declared activity.
- Manifests of all source sets under `android/app/src/*` are consulted. If the namespace cannot be read, names are compared by their last segment (ambiguous matches count as declared, so nothing is reported).
- Manifests contributed by dependencies are not visible. A build was not run for this rule: a missing activity declaration is not a build error, so it is only found statically.

**Not established by the documentation:** the `android:exported` value for a configuration activity (the documented snippet omits it; Android 12+ requires an explicit value whenever an intent-filter exists), and how a relative `android:configure` value is treated.

**Fix:** Declare the activity with an `android.appwidget.action.APPWIDGET_CONFIGURE` intent-filter and an explicit `android:exported` (the fix text suggests `"true"`), or remove `android:configure`.
